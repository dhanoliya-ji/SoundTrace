# Dataset and manifest

The official AVSBench-object release has `Single-source` (S4) and `Multi-sources` (MS3) subsets. Official metadata CSVs identify video, category, and train/valid/test split. The official implementation uses five one-second clips and paired per-second audio features; it samples a frame at the end of each second. S4 training provides only the first annotated frame, while S4 validation/test and MS3 use five annotated frames. This is why generic full-video random splitting or pairing masks by approximate timestamp is not equivalent to the benchmark protocol.

Use `python -m soundtrace.cli build-manifest --config configs/s4_baseline.yaml --task s4 --data-root $env:SOUNDTRACE_DATA_DIR` or the equivalent MS3 config/task. The adapter follows the [official S4 loader](https://github.com/OpenNLPLab/AVSBench/blob/main/avs_scripts/avs_s4/dataloader.py) and [MS3 loader](https://github.com/OpenNLPLab/AVSBench/blob/main/avs_scripts/avs_ms3/dataloader.py): S4 frames and masks are under split/category/video folders with per-video `.pkl` log-mel audio files; MS3 frames are grouped by video and masks/features by split. It emits one record for the only labeled S4 training frame and five records for S4 validation/test and MS3. Missing frames, masks, or audio features are reported as errors. The official Python pickles are loaded as trusted local dataset files. The adapter has been checked against the public loader paths and generated fixtures, but not against an acquired release; inspect the generated manifest before training.

`build-manifest` with its default `inventory` task scans candidate files and pairs only matching stems as an inventory aid; those records are marked `review_required` and training rejects them. Do not infer official annotation pairing from filenames alone. Obtain the release using the official project instructions, inspect its readme and annotations, and preserve its source-video-level split.

Training records may use processed `frame` images plus an `audio_features` file and `audio_index`, or a raw `video` path with FFmpeg-decoded waveform audio. The AVSBench adapter consumes its five-clip log-mel features directly; generic waveform manifests use SoundTrace's compact waveform encoder. Neither path reproduces the official VGGish model, image normalization, TPAVI fusion, training objective, or official metric in full. This is a research prototype, not an official AVSBench reproduction. `load_mask` converts nonzero grayscale pixels to binary foreground using nearest-neighbor resizing. Class labels and AVSS semantics are not implemented.

Split by source video before deriving frames, crops, windows, or caches. Check unique `video_id` sets for overlap. Dataset readiness and all missing/corrupt/unmatched items must be reviewed before training. Set `SOUNDTRACE_DATA_DIR` or use the manifest config. Do not commit source media, annotations, or derived restricted assets.
